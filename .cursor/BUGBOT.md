# convert-service（QuickConv）レビュー観点（Bugbot）

唯一の収益プロダクト。`apps/web`（フロント）/ `apps/api` / `apps/converter` /
`packages/shared` の turbo monorepo。**ユーザーがアップロードしたファイルを処理する**ため、
入力検証とファイル取り扱いの欠陥が直接インシデントになる。

## 出力ルール

- コメントは**日本語**で書く。
- 各指摘に **`must` / `should` / `nit`** を明記する。`must` はマージをブロックする欠陥に限る。
- typo・整形のみの nit は省略する。
- `.claude/worktrees/**` は作業用 worktree なのでレビュー対象外。

## must として扱う観点

### 1. アップロード入力の検証
ファイルサイズ上限・MIME / マジックナンバー検証・拡張子の信頼、
ファイル名由来のパストラバーサル（`../`）、展開後サイズの上限（zip bomb 相当）。
検証を緩める・上限を上げる変更は理由とセットでないと must。

### 2. 一時ファイルのライフサイクル
変換の中間ファイル・アップロード原本が削除されずに残る経路。
失敗パス・例外パスでも cleanup が走るか。他ユーザーが到達できる場所に置いていないか。

### 3. 課金・決済経路
金額計算・プラン判定・上限チェックの変更。無料枠の判定を緩める変更。
Stripe 等のシークレットのハードコード。

### 4. 機密
Cloudflare / GCP の認証情報、`.env` の値のログ出力、
エラーレスポンスへのスタックトレース・内部パスの露出。

### 5. 層をまたぐ責務越境
`apps/web` が `apps/api` の内部実装に直接依存する、`packages/shared` が
特定 app にしか意味のない知識を持つ、といった依存方向の逆転。

### 6. サイレントフォールバック
変換失敗を握りつぶして壊れたファイルを返す、`catch {}`、
エラーを空レスポンスに潰す。失敗は明示的に返すこと。

## should として扱う観点

- SEO: `<title>` の長さ（検索結果で切れる）、メタ・OGP・sitemap の整合
- TypeScript: `any` の使用、外部入力（リクエストボディ・クエリ）のランタイムバリデーション欠落
- `turbo build` / `turbo lint` が通るか、prettier フォーマット
- 新規ロジックにテストが無い
- submodule `tools/team_salary` の pointer を、元リポの PR merge 前に bump していないか
