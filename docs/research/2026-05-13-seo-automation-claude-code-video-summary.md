## TL;DR

Claude Code をオーケストレーターとして使い、**7種類のサブエージェント** + **HITL（Human-in-the-Loop）** で SEO オウンドメディア運用を完全自動化する仕組み。投稿者は実運用で **1日2記事 / 月60本** を **月額2-3万円のClaude Code料金** で回しているとのこと。動画末尾でこの一連の仕組みを「公式LINE登録特典として全部プレゼント」する旨を訴求している（リードマグネット動画）。

## 2. アーキテクチャ（7エージェント体制）

```
[Phase 1: キーワード選定]
  ↓ Ahrefs MCP + SEOナレッジ
[Phase 2: リサーチ（X / YouTube 一次情報）]  ← EEAT の "Experience" 担保
  ↓
[Phase 3: 競合分析（上位10記事の H2/H3 抽出）]
  ↓
[Phase 4: 構成設計]
  ↓
[Phase 5: 執筆（3エージェント並列）]
  ↓
[Phase 6: 品質スコアリング（100点満点・95点未満は再執筆ループ）]
  ↓
[Phase 7: 公開（WordPress入稿 + Google Search Console インデックス登録）]
  ↓
[Phase 8: 分析（GA4 + Search Console → 次回キーワード選定にフィードバック）]
```

- **HITL ポイント**: Phase 6 と Phase 7 の間で人間が最終チェック（「これは投稿していい？」を確認）
- **オーケストレーター**: Claude Code が「中間管理職」役

## 4. EEAT 観点での工夫

発信者は以下を強調:

1. **Experience（経験・一次情報）**: X と YouTube から「実際に触っている人」のナレッジを引っ張ってきて記事に反映
2. **監修者の明示**: 著者プロフィール（X リンク等）を記事フッターに表示
3. **画像生成**: Gemini "Nano Banana" API でアイキャッチ + H2直下画像を自動生成
4. **ナレッジファイル**: 発信者が貯めた SEO ナレッジ（YouTube 動画群を要約したもの）を Claude Code に毎回ロード

## 8. QuickConv 文脈での適用可能性（初期所見）

### Pros
- QuickConv は **既に `docs/articles/` でSEO記事運用中**。投稿実績あり
- `tools/team_salary` submodule に **note / Qiita / SNS 投稿基盤が既存**（重複実装の必要なし）
- ローンチ Phase 3（Epic #225）で「ローンチバースト + SEOが主軸」と memory に明記済み
- Cloudflare Pages デプロイ済みで記事の置き場所インフラは整っている

### Cons / Risks
- **WordPress を使っていない**: QuickConv は Next.js + Cloudflare Pages。動画の前提（WordPress自動入稿）が直接適用できない
- 上記の主張C1-C6が未検証
- 「無料配布スキル」の中身が不明（動画では概念のみ）
- **コンテンツの薄さでGoogleペナルティリスク**: 月60本ペースは E-E-A-T のExperience要件と矛盾する懸念
- 既存記事（005 / 004 シリーズ）の運用フローと統合する必要がある

### 既存資産との重複チェック
- 既存: `tools/team_salary/scripts/` 配下に記事執筆〜投稿の自動化スクリプト群
- 既存: QuickConv に `docs/articles/README.md`（流用元モジュール一覧）
- 既存: GA4 / Search Console 連携（Issue #11 ローンチ計画で言及）
