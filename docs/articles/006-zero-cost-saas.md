「個人開発で SaaS を作ったけど、月数千円のサーバー代がジワジワ効いてくる」──これは個人開発者あるあるです。AWS の小さな EC2 でも `t3.small` で月 $15 程度、RDS を足すと $30 を超えてしまい、ユーザーが付く前に毎月の固定費だけで赤字になります。

画像変換サービス [QuickConv](https://quickconv.cc) は、**月額ほぼ 0 円**で運用しています。Cloudflare Pages / Workers / R2 / D1 + GCP Cloud Run の無料枠を組み合わせ、トラフィックが急増した時にだけ従量課金が走る構成です。

この記事では、実際の構成図・各サービスのコスト・「無料枠で運用する時にだけ気を付けるべきポイント」を、運営者の立場で解説します。

## 1. なぜ月額 0 円を目指したか

QuickConv は「副業として続けられる赤字にならない収益モデル」を前提に設計しました。SaaS の場合、サーバー代がそのまま固定費になるため、ユーザーが 1 人もいない初月から数千円が消えていきます。

個人開発で「月額固定費ゼロ」を実現できると、次のメリットがあります。

- **ローンチ前の検証フェーズで赤字にならない**: ユーザー獲得 0 でも費用 0
- **収益化に焦らなくて済む**: 月数十人のユーザーでも黒字
- **ピボット・撤退の心理的コストが下がる**: いつ閉じても傷が浅い

サブスク化したい SaaS であれ、買い切り型のミニアプリであれ、固定費ゼロから始めて従量で増やす設計は最も精神衛生に良い選択です。

## 2. アーキテクチャ全体像

QuickConv の構成は次のようになっています。

```text
┌─────────────────────────────────────────────────────────────┐
│  [Browser]                                                  │
│      │                                                      │
│      ▼                                                      │
│  Cloudflare Pages (Frontend: Next.js 静的エクスポート)      │
│      │                                                      │
│      ▼                                                      │
│  Cloudflare Workers (API: Hono)                             │
│      │                                                      │
│      ├──→ Cloudflare R2 (一時ファイル / 24h 自動削除)       │
│      ├──→ Cloudflare D1 (ユーザー / 課金記録)               │
│      └──→ GCP Cloud Run (Sharp で実際の画像変換)            │
└─────────────────────────────────────────────────────────────┘
```

**設計のポイント**:

- **フロントエンドは静的エクスポート**: Next.js を SSG モードで吐き出して Cloudflare Pages に上げるだけ。SSR を諦める代わりに、ビルド済み HTML/JS を CDN から配るだけなのでサーバー実行費がかからない
- **API はエッジで完結**: 認証・ファイル受付・課金連携は全て Workers 上で完結。重い処理だけ Cloud Run に逃がす
- **ストレージは R2 で「持たない」**: アップロードファイルは 24 時間で自動削除し、永続データは D1 のメタデータだけにする

## 3. 各サービスのコスト（無料枠の上限と実利用）

QuickConv が実際に使っているサービスごとの無料枠と、現状の使用量です（2026 年 5 月時点）。

| サービス | 無料枠 | QuickConv の使用量 | 月額 |
|---|---|---|---|
| Cloudflare Pages | ビルド 500 回 / 月、リクエスト無制限 | ~30 ビルド | 0 円 |
| Cloudflare Workers | 10 万リクエスト / 日 | ~3,000 / 日 | 0 円 |
| Cloudflare R2 | 10GB ストレージ、エグレス無料 | ~1GB（24h 自動削除のため一定） | 0 円 |
| Cloudflare D1 | 5GB ストレージ、500 万読取/日、10 万書込/日 | <100MB | 0 円 |
| GCP Cloud Run | 200 万リクエスト / 月 | ~10,000 / 月 | 0 円 |
| Sentry (エラー監視) | 5,000 events / 月 | ~50 / 月 | 0 円 |
| ドメイン (quickconv.cc) | — | — | 年 ~1,500 円 |
| **合計** | | | **月 ~125 円**（ドメイン按分のみ） |

ドメイン代を除けば**完全に 0 円**です。トラフィックが 100 倍になっても、Cloudflare 側はエッジ無料枠が広く、Cloud Run も 200 万リクエスト / 月の枠があるので、月数千円程度に収まる試算です。

## 4. 無料枠で運用する時の落とし穴

ここからが本記事の本題です。「Cloudflare 無料枠で組めば 0 円」という話自体は珍しくありませんが、実際に運用してみると幾つか落とし穴があります。

### 落とし穴 A: AWS S3 から R2 に移すと「エグレスが化ける」

S3 から画像をダウンロードさせると、エグレス（外向きトラフィック）に **$0.09 / GB** がかかります。月 1TB 配信したら $90 = 13,500 円です。

R2 はエグレスが**完全無料**です。同じ 1TB で 0 円。これが Cloudflare の最大の差別化ポイントで、「ストレージが安い」より「外向き通信が無料」の方が個人開発には効きます。

ただし、R2 の API は S3 互換ですが、**SDK のリージョン指定**でハマることがあります。`auto` を指定する必要があり、`us-east-1` のような S3 リージョンを書くと 403 が返ります。

```ts
// NG: S3 のクセで書きがち
const client = new S3Client({ region: "us-east-1", endpoint: R2_ENDPOINT });

// OK: R2 では region: "auto"
const client = new S3Client({ region: "auto", endpoint: R2_ENDPOINT });
```

### 落とし穴 B: Cloudflare Workers の CPU 時間制限

Workers の無料枠は「リクエスト数」だけ見ると緩いですが、**1 リクエストあたりの CPU 時間 10ms**という別の制約があります。画像変換のような重い処理を Workers 上でやるとすぐに超過します。

QuickConv の場合、Sharp を使った実際の変換処理は **Cloud Run に逃がしています**。Workers は受け付けと認証・課金チェックだけ。これにより 10ms の上限を気にせず済みます。

### 落とし穴 C: D1 の書込は単一リージョンに制限される

D1 は SQLite ベースで、書込は**プライマリーリージョン 1 つ**に集約されます。読取はエッジレプリカで分散されますが、書込が多いワークロードでは書込パフォーマンスが頭打ちになります。

QuickConv では「変換ログ」「課金イベント」など書込の多いデータは [Stripe](https://stripe.com) や [PostHog](https://posthog.com) に逃がし、D1 にはユーザーマスタとサブスクリプション状態だけを置いています。

### 落とし穴 D: Cloud Run の cold start

Cloud Run の無料枠は「**min-instances = 0**」が前提です。リクエストが来ない時間帯はインスタンスがゼロになり、次のリクエストで起動コストが乗ります（コンテナサイズによりますが Sharp 入りのイメージで ~2 秒）。

これを許容できないなら min-instances を 1 にする必要がありますが、その瞬間から月 1,500 円〜が発生します。QuickConv は許容しています（変換は元々数秒かかるので体感差が小さい）。

## 5. 同じ構成を別ジャンルの個人開発でも使えるか

「画像変換だから R2 が活きる」のは事実ですが、構成パターン自体は他のジャンルでも横展開できます。

| あなたが作りたいサービス | 流用できる構成 | 注意点 |
|---|---|---|
| ブログ / 個人サイト | Pages + D1 + R2（画像） | コメント機能を追加したら Workers + D1 で受ければ良い |
| 簡易な SaaS（フォーム / TODO） | Pages + Workers + D1 | 重い処理が無いなら Cloud Run も不要、完全 Cloudflare 完結 |
| メディア配信 | Pages + Workers + R2 + Stream | 動画は Cloudflare Stream の有料プランが必要（月額 $5〜） |
| AI ラッパーサービス | Pages + Workers + Cloud Run（推論） | OpenAI / Anthropic の API 代が別途必要 |

特に「Pages + Workers + D1」のトリオは、SaaS のフロントエンド + API + データの最小構成として非常に強力です。サーバーを 1 台も立てずに済みます。

## 6. まとめ

個人開発の SaaS を「**月額固定費ゼロ**」で始める構成として、Cloudflare の無料枠は 2026 年現在ベストの選択肢です。

ポイントを 3 つに絞ると、

1. **エッジで完結させる**: フロントは静的エクスポート + CDN、API は Workers でエッジ実行
2. **重い処理だけ逃がす**: Cloud Run など従量課金の場所に局所化し、cold start を許容
3. **R2 のエグレス無料を最大限活かす**: ストレージ系のサービスでは特に効いてくる

QuickConv はこの構成で月 1 万リクエスト規模を 0 円で捌いています。同じパターンは、ブログ・SaaS・AI ラッパーなど色々な個人開発に流用できます。
