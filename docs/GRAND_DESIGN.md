# QuickConv グランドデザイン

## ミッション

次世代画像フォーマット（WebP/AVIF/HEIC）の変換を、誰でも無料で・登録不要で・高品質に行えるサービスを提供する。

| 項目 | 内容 |
|---|---|
| サービス名 | QuickConv |
| URL | https://quickconv.cc |
| API | https://api.quickconv.cc |
| ターゲット | SNSユーザー・ブロガー層 → 順次拡大 |
| 差別化 | 次世代画像フォーマット特化 + 品質比較プレビュー |
| 位置づけ | 個人副業プロジェクト（低コスト運用必須） |

## 技術スタック

| レイヤー | 技術 | 理由 |
|---|---|---|
| Frontend | Next.js (App Router) + Tailwind + shadcn/ui | SSG対応、SEO最適化 |
| API | Hono on Cloudflare Workers | エッジ実行、無料枠大 |

## 開発運用方針

### 自律開発原則
- **Claude は自律的に開発を進める**。ユーザーへの質問は最終手段
- 問題が発生したら AgentTeams を自律招集し、専門家チームで解決する
- ユーザーへの質問が必要な場合は **Pushover通知** で連絡する

### 開発フロー（1 Issue あたり）
1. **Issue解析**: Issue の AC・依存関係を確認
2. **調査**: 必要に応じて AgentTeams で技術調査
3. **実装**: ブランチ作成 → コード実装 → テスト
4. **Push**: `git push origin <branch>`
5. **PR作成**: `Closes #XX` を必ず含める（ロードマップ自動連携）

### 優先順位の決定
- **依存度が高い順**（他のIssueのブロッカーになるものを先に）
- **重要度が高い順**（収益化に直結するものを優先）
- ロードマップ（GitHub Projects）を参照して着手順を決定

### PR ルール
- PR の body に `Closes #XX` を必ず含める
- PR マージ時に GitHub Actions が自動で:
  - 対応 Issue の Target date をセット
  - ステータスを Done に変更

### ボトルネック対応
- ユーザー介入が必要な場合（機密情報、外部アカウント設定等）のみ Pushover 通知
- 技術的な問題は AgentTeams で自己解決

## 設計原則

1. **コスト最小**: 無料枠を最大限活用。有料サービスは需要が証明されてから
2. **シンプル第一**: 機能追加より既存機能の品質向上を優先
3. **SEO駆動**: 全ページがSEO最適化済み。集客の主軸
4. **段階的収益化**: 無料 → 広告 → 買い切り → サブスク → API の順
5. **データ駆動**: GA4 で計測し、数字で判断する
